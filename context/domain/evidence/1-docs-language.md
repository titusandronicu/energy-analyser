## Lifecycles

Each is `evidence`; missing transitions are marked.

**L1 Live snapshot freshness.** States: current ("aktualne") -> watch ("dane sprzed ...") -> problem ("brak nowych danych od ..."); degraded flag; "Nothing received yet is insufficient." Mover: elapsed time since `captured_at`; thresholds 15 min and 2 h; "staleness wins over degraded". Source `docs/logic.md:145`, `:29`. Missing: no documented transition for a future `captured_at` ("The live state has no future guard", `docs/logic.md:120`).

**L2 Recommendation.** Generated by the lab (about hourly), pushed, then aged by clock: good ("aktualna") when generated today within 2 h -> watch ("sprzed ...") when from today but older -> problem ("z <day> — dotyczy innego dnia") when generated before today; problem ("czas z przyszłości") when more than 5 minutes ahead of the app clock. Nothing received yet is insufficient. In the calendar a past day's advice "is not judged against today: its badge is neutral". Sources `docs/logic.md:119-120`, `:147`, `:177`. A repeated `generated_at` "keeps the first text" (`:118`). Missing: no state for withdrawal or deletion (unknown, searched: logic.md, decisions.md, architecture.md).

## Multiple meanings (context boundaries)

1. **"norm"**: (a) usage norm = median consumption (kWh) of the baseline days, seasonal or 30-day (`docs/logic.md:84`); (b) rating norm = median self-sufficiency of the previous 14 days (`:188`); (c) "daily norm" for the Home node = usage norm x hours elapsed / 24 (`:54`). Different quantity, window and unit.
2. **"fallback"**: 30 days for the insight (`docs/logic.md:82`) vs the rating's recent 14-day norm described as the same rule in the PRD ("the same rule as FR-003", `prd-v3.md:214`) but implemented with a 14-day window (`docs/logic.md:188`; `docs/decisions.md:78`).
3. **"complete day"**: (a) calendar: PV, load, import present, before today (`docs/logic.md:171`); (b) hourly: every clock hour of the date present and complete, 24/23/25 (`:101`); (c) lab daily totals: counters read correctly and data to the end of the day (`:223`); (d) lab summaries: usable sample at or after 23:00 (`:277`); (e) bill forecast: same rule as (c), today never counted (`:234`). Five definitions; (a) and (b) can disagree.
4. **"forecast"**: PV production forecast (Solcast, `docs/logic.md:226`) vs bill forecast (`:228`) vs "weather forecast" in PRD v1/v2 (replaced, `prd-v3.md:182`). Also "Forecast certainty" (PV) vs bill forecast "confidence" (`:239`) vs the lab's optional `confidence` field, which is ignored (`:130`).
5. **"recommendation"**: the daily battery advice (`prd-v3.md:175`); "consumption-plan recommendations" in FR-013 (`prd-v3.md:191`), a different lab artefact shown as manual actions.
6. **"summary"**: lab period summary text (`docs/logic.md:274`) vs "summaries" of the rating "basis" vs "Pełne dane" counts. Within the PRD, "summary" is a lab-written LLM text (FR-023, `prd-v3.md:215`).
7. **"feedback"**: removed recommendation accept/dismiss feedback (`prd-v3.md:77`) vs "no timely feedback on energy cost" (`prd-v3.md:19`) vs UI "continuous visible feedback" (`prd-v3.md:260`).
8. **"verdict" / "rating" / "tone" / "status"**: node verdict (good, watch, problem; `docs/logic.md:36`), usage verdict (normal, above, below; `:85`), bill verdict (`:257`), rating (good, neutral, bad; `:189`), status tone (`:136`). Neutral grey means three things: "za mało danych", "Przeciętny dzień", "Bez oceny" (`:60`, `:194`).
9. **"import"**: grid import as the inverter reports it (`docs/logic.md:158`), grid import as PGE bills it (hourly-balanced, `:103`), "imported energy" of the month in the bill forecast (`:234`).
10. **"period"**: data period (text, `:151`), billing period (`:232`, `settlement.reference_period` `:259`), calendar period (`:167`), summary `period` (date or month, `docs/ingest/README.md:25`).
11. **"today" / "dziś" / "jutro"**: relative to the recommendation's generation day, not the reader's (`docs/logic.md:128`); live "today" totals are partial (`:67`); the calendar's today is never complete (`:171`).
12. **"owner" / "user"**: `app_owners` membership (database role, `README.md:30`) vs the sole human persona (`prd-v3.md:28`); the PRD says "no roles" (`prd-v3.md:277`) while the model has owner vs non-owner. `inference`: roles exist only as an access check, not as business roles.
13. **"access key"**: PRD wording "access key (token/link)" (`prd-v3.md:146`) vs the running sign-in "emailed magic link or password" (`README.md:7`) vs the ingest "bearer token" (`docs/ingest/README.md:58`) (a different secret, for the lab).
14. **"hour"**: a clock hour of house use vs "hour of the day" count in the usage profile (aggregate, `prd-v3.md:192`) vs "hour done" for PV share (`docs/logic.md:46`).
15. **"stale"**: live (15 min), recommendation (2 h or earlier day), bill forecast (30 min on `generated_at`), today's summary (2 h from narration time) - four clocks (`docs/logic.md:145`, `:147`, `:255`, `:292`).
