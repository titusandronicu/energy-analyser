# Break proof: one deliberate break per risk

Run 2026-10-05. Each break lived on a throwaway branch off `test/quality-gates-wiring` with a draft PR to `main`, pushed with `HUSKY=0` so the local pre-push gate did not hide the CI result. With the ruleset `main-quality-gates` active, every PR below showed `mergeStateStatus: BLOCKED` as soon as a required check failed. All six PRs (#122 to #127) and their branches were deleted afterwards; `git diff origin/main -- src supabase` is empty on the change branch.

## Notes

- **#122 also turned `integration` and `smoke` red.** The `warsaw-time.ts` break is shared code used by the integration and smoke paths, so it is not a clean single-check proof for `integration`; the unit-only breaks for #1, #2 and #6 are visible in the `ci` log by test file.
- **#126: the notes server limit is guarded by `ci` only.** `integration` and `smoke` stayed green with the server limit at 501, because `notes-parity.test.ts` checks the database limit and the real `saveNote` against 500-character text, not `NOTE_MAX_LENGTH` drift in isolation. The unit tests cover that side, so the risk is still caught before merge; recorded as a boundary of the integration suite, not a hole in the gate.
- **#127: lint is the first guard for `set:html`**, ahead of the static `render-safety` test; either would block.
- **Cleanup**: PRs #122 to #127 closed with their branches deleted; no break reached `main`.
